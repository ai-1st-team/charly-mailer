# Decisions

## 2026-05-23 — Финальный набор вкладок

Принято: в приложении есть ровно пять вкладок — Setup, Content, Campaign, Send, Stats.

Почему: следующие задачи ссылаются на эти области, поэтому навигацию фиксируем сразу и дальше только наполняем вкладки.

## 2026-05-23 — Разделение GUI и core

Принято: GUI-модули отвечают за отображение и события, `core/` — за бизнес-логику.

Почему: это позволит тестировать SMTP, прокси, контент, очередь и статистику отдельно от интерфейса.

## 2026-05-23 — data/ и logs/ вне git

Принято: содержимое `data/` и `logs/` добавлено в `.gitignore`, но `.gitkeep` оставлен отслеживаемым.

Почему: там будут приватные SMTP-данные, конфиги кампаний и рабочие JSON-логи.

## 2026-05-23 — Повторная загрузка прокси заменяет источник

Принято: при повторной загрузке из того же файла или URL старые прокси этого источника удаляются и заменяются новым списком.

Почему: URL-списки могут обновляться, и stale-прокси не должны бесконечно оставаться в текущей сессии.

## 2026-05-23 — Пароли прокси скрываются в GUI и logs

Принято: полный proxy URL хранится только внутри `ProxyRecord.proxy_url`, а в интерфейсе и JSON-логах используется `display_name` с `***`.

Почему: прокси могут содержать чувствительные credentials.

## 2026-05-23 — SMTP-пароли не выводятся в интерфейс

Принято: `SMTPAccount.password` хранится только внутри модели и используется для `smtplib.login()`, но не попадает в GUI, README или JSON-логи.

Почему: `smtps.txt` содержит чувствительные credentials.

## 2026-05-23 — SMTP шифрование определяется по порту

Принято: `465` использует SSL, `587` использует STARTTLS, `25` использует STARTTLS только если сервер объявил поддержку.

Почему: это ожидаемое поведение SMTP-провайдеров и не требует ручной настройки на первом этапе.

## 2026-05-23 — SMTP proxy tunnel без новой зависимости

Принято: для SMTP через прокси реализован HTTP CONNECT tunnel на stdlib `socket/ssl`, без PySocks.

Почему: проект держит минимум зависимостей, а текущий формат прокси — HTTP.

## 2026-05-23 — Комментарии в subjects.txt не игнорируются

Принято: `storage.read_text_lines()` получил параметр `ignore_comments`; для тем он выключен.

Почему: в задаче по темам сказано игнорировать только пустые строки, значит строка, начинающаяся с `#`, может быть валидной темой письма.

## 2026-05-23 — Тема выбирается на каждое письмо

Принято: случайный выбор темы вынесен в `SubjectManager.render_random()`.

Почему: будущий sender должен получать уже готовую тему для конкретного получателя и отправителя, не дублируя логику плейсхолдеров.

## 2026-05-23 — Спинтакс парсится через AST

Принято: вложенный спинтакс в телах писем разбирается рекурсивным AST-парсером, а выбор вариантов происходит при рендере.

Почему: регулярные выражения плохо работают с произвольной глубиной вложенности.

## 2026-05-23 — Фигурные скобки без | считаются текстом

Принято: конструкция `{...}` без разделителя `|` на текущем уровне не считается спинтаксом.

Почему: тела могут быть HTML/CSS, где фигурные скобки встречаются как обычный текст.

## 2026-05-23 — Один LinkRenderContext на письмо

Принято: уникальность ссылок контролируется через общий `LinkRenderContext`, который передаётся и в тему, и в тело.

Почему: настройка `уникальные ссылки в письме` должна работать на письмо целиком, а не отдельно на тему и отдельно на тело.

## 2026-05-23 — Имя links-файла задаёт макрос

Принято: `links.txt` соответствует `[[LINK]]`, `links1.txt` соответствует `[[LINK1]]`, `links2.txt` соответствует `[[LINK2]]`.

Почему: это простое правило позволяет держать несколько оферов без дополнительного конфига.

## 2026-05-23 — StatsManager как singleton

Принято: `core.stats.get_stats_manager()` возвращает общий `StatsManager` для GUI и будущего sender.

Почему: вкладка `Stats` должна видеть обновления из фонового потока отправки без сложной передачи зависимостей через все вкладки.

## 2026-05-23 — Дневной campaign log как JSON-массив

Принято: основной лог кампании пишется в `logs/YYYY-MM-DD.json` как валидный JSON-массив.

Почему: задача требует `.json`, а экспорт JSON должен отдавать готовый структурированный файл.

## 2026-05-23 — AppState как shared runtime state

Принято: вкладки `Setup`, `Content`, `Send` и будущая `Campaign` работают через `core.app_state.get_app_state()`.

Почему: загруженные SMTP/прокси/контент должны быть доступны sender без ручного прокидывания объектов между вкладками.

## 2026-05-23 — Test send отдельно от campaign stats

Принято: тестовая отправка пишет только `logs/test-log.json` и не вызывает `StatsManager.record_delivery()`.

Почему: тесты не должны портить метрики основной кампании.

## 2026-05-23 — Cooperative stop

Принято: `CampaignController.stop()` ставит event и даёт текущему письму завершиться.

Почему: жёсткое убийство потока может оставить SMTP-соединение и queue-state в неконсистентном состоянии.

## 2026-05-23 — CSV база хранит только email/name

Принято: при загрузке базы в `AppState.recipients` сохраняются только `email` и `name`.

Почему: текущие плейсхолдеры используют только эти поля, а лишние колонки могут содержать приватные данные и пока не нужны.

## 2026-05-23 — Control recipients вставляются на этапе QueueManager

Принято: control-инжект делается при построении очереди, а не в sender loop.

Почему: очередь и resume-state должны отражать реальные будущие отправки, включая control-письма.

## 2026-05-23 — Sender name выбирается один раз на письмо

Принято: `EmailComposer` выбирает случайное имя отправителя один раз и использует его и для `From`, и для `{{senderName}}`.

Почему: заголовок письма и текст письма должны быть согласованы.

## 2026-05-23 — Email-only From без fallback-имени

Принято: если включён режим `использовать только email без имени`, `AppState.choose_sender_name()` возвращает пустую строку.

Почему: задача требует, чтобы From содержал только SMTP email, без автоматически сгенерированного display name.

## 2026-05-23 — BCC хранится в MIME до send_message

Принято: `EmailComposer` добавляет `Bcc` в `EmailMessage`, а отправка идёт через `smtplib.send_message()`.

Почему: stdlib сам использует BCC как envelope recipients и не раскрывает заголовок в сериализованном письме.

## 2026-05-23 — Preset load очищает runtime перед загрузкой

Принято: загрузка пресета очищает старые прокси, SMTP, контент, базу и дополнительные настройки перед перечитыванием файлов.

Почему: смешивание старой кампании и нового пресета опаснее, чем явное предупреждение о пропавшем файле.

## 2026-05-23 — Лаунчеры не собирают exe

Принято: `start.bat` и `start.command` устанавливают зависимости и запускают `main.py`, без PyInstaller.

Почему: запуск через Python проще поддерживать, а сборка exe пока необязательна.
